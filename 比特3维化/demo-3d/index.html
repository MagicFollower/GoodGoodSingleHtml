读这张图之前，先记住三句话

  1. 三维是视图，不是存储。容器里没有任何三维数组；z = 层号、(x,y) = 螺旋闭式(层内比特序号)，两者都能从比特序号即时算出，一个字节都不多占。
  2. 前四步只搬位置，最后一步才改值。螺旋、仿射、秩压缩都是双射的位置变换 —— 原文有多少个 1，容器里就有多少个 1。只有 ChaCha20 异或改变值。
  3. 它是混淆，不是加密。数据密钥 dek 明文躺在头部偏移 64..95，任何拿到容器的人都能完整还原。机密性强度 0 bit。

1 · 项目基本介绍

1.1 它做什么

把任意文件重编码成一个自定义容器 .bt3d：文件按 128 KiB 切成层，每层的比特按逆时针螺旋填进 1024×1024 的平面格子，格子序号再经密钥相关的仿射变换打散、经秩压缩紧凑化，最后整层与 ChaCha20 密钥流异或落盘。总大小 = 原文件 + 恰好 128 字节。

五步全是双射 ⇒ 整体可逆。约定 C4：光栅方向是 y 升序（底行优先），与图像光栅相反 —— 照抄图像代码会上下翻转。

1.2 三层机制各修掉什么问题

机制解决的问题关掉会怎样
螺旋 s↔(x,y)把线性比特流铺成二维面，并提供三维解释盘面退化成一维条带
仿射 r=(a·q+b) mod 2²⁰修掉螺旋的50% 恒等邻接泄露原文件前 128 字节被原样抄进容器
秩压缩 r'=rank(r)末层不必补满一整层1 字节的文件膨胀成 128 KiB
密钥流 ChaCha20 异或消除压缩率指纹、位占比指纹、公共子串值的分布仍是原文的分布

第 3 节把这四个开关逐个关掉，看盘面怎么变。

1.3 为什么仿射散射非有不可

存储扫描 q = y·1024 + x 在 x 方向连续，而螺旋的每条边里，下边沿 x 向右、上边沿 x 向左 —— 于是这两条边上「来源序号 s 步进 +1」与「盘面位置步进 ±1」重合，位置几乎没被打散。四类边各占正好 25%，所以是 50% 的比特仍然紧邻。

这不是参数没调好，而是一般性结论：只要存储扫描在 x 方向连续，两条水平边就必然落在 |Δq| = 1 上 —— 与起点选哪个角、顺/逆时针、y 朝上朝下、从哪一圈开始全都无关。最外圈下边覆盖 s = 0..1022 → q = 0..1022，紧接着右边第一格 s = 1023 → q = 1023，于是 payload 的前 1024 比特 = 原文件前 1024 比特 = 前 128 字节逐字节相同。

1.4 工程结构

零第三方依赖，只用 node:crypto / node:zlib / node:fs。四层结构，机制层五个模块互不依赖、只依赖契约层；codec.js 是唯一知道「层循环」存在的地方。

2 · 项目各个参数的介绍

2.1 前 128 字节：真实头部的逐字节切片

下面这条色带是本次实跑产出的那个容器的头部（规范挡 flags=0x1c），128 个格子一格一字节，按字段着色。鼠标移到任意一格，下方表格会高亮它属于哪个字段并显示解析值。

偏移长度字段类型规范值 / 范围本次实跑值说明

加总核对：4+1+1+2+8+8+4+4+12+20+32+32 = 128，逐字节全覆盖、无空洞。多字节整数一律小端（约定 C1）。

2.2 flags 字节逐位（偏移 5）

规范 profile = bit2 + bit3 + bit4 = 4+8+16 = 28 = 0x1C。第 3 节的四挡阶梯就是按 bit3 → bit4 → bit2 的顺序逐个打开这三个位。

位权重常量名规范值含义关掉会怎样

两个掩码 FLAGS_NORMATIVE=0x1C / FLAGS_MUST_BE_ZERO=0xE3 都由各个位常量算出来，并在模块加载时断言并集为 0xFF、交集为 0x0。规格初稿曾把手写的必零掩码写成 0xC3（漏了 bit5），后果是 COMPRESSED=1 的畸形容器会静默通过校验。

2.5 五条硬性约定 —— 跨实现互通的全部前提

#约定规范值不一致的后果
C1字节序头部所有多字节整数一律小端头部字段全部读错
C2位序MSB-first：(B >> (7−j)) & 1每字节内 8 比特倒序。写反了往返照样绿，只有黄金向量能抓
C3坐标系手性x 右、y 上、z 向屏幕外；逆时针 = 从 +Z 向 −Z 俯视屏幕坐标 y 向下会让同一段代码输出顺时针，两份实现互为镜像
C4光栅方向q = y·1024 + x，y 升序（底行优先）与图像光栅相反，照抄图像代码会上下翻转
C5全局比特序号i = 字节序号 × 8 + 位序号，位序号按 C2与 C2 联动

本页三维盘面的铺法遵循 C3/C4：y = 0 那一行（原文件前 128 字节所在）画在朝向观察者的前缘。金色的前缘标记线沿外法线挪到盘外一侧 —— 压在同一行上会盖掉该行自己的像素，而那一行正是 D1 挡要展示的青色落点。

画布上按住左键拖动 = 同时改方位角与仰角；滚轮 = 以光标为锚缩放（0.4×–8×）；右键或 Shift 拖动 = 平移；「复位视角」把角度、层距、缩放、平移一次清干净。×1.00 就是自适应铺满那一态，此时右侧「是否越界」才成立；放大后画面本就该被画布裁掉。切换挡位时视角、缩放与叠加保持不变，便于逐格对比。

    编号圆牌落在取景包围盒之外，引线指向由投影式子现算的锚点 —— 旋转、缩放、平移之后仍指着同一个地方；标在图案自己身上的做法这一轮栽过：金线压在它标记的那一行上，把 D1 的青色落点整个糊掉了。标记当前条件不出现的行会灰掉。

    四个小图与大图共用同一组角度参数，但不跟缩放与平移 —— 各自铺满自己那格，职责是并排对照。D2 / D3 / OK 的几何完全相同（同一个仿射键），所以它们的盘面排布一致，差别只出现在末层与值分布上；D1 是另一个几何键，一眼就能看出区别在哪。

    3.2 实测指标对照

    绿 = 达到规范阈值；红 = 未达标；灰 = 该挡不适用。判据编号沿用仓库的冻结编号（1~15 只追加不重排）。所有数来自 node build-data.mjs 这一次实跑，不是引用 README 的台账。

    3.3 近景：盘面与「前 128 字节」的逐格对照

    左：第 0 层盘面按存储序号铺（也就是它在容器里真的怎么排），红=恒等邻接、青=前 1024 比特的落点。右：payload 最前面 128 字节展开成 128×8 的比特格，与原文同样排布并列 —— 相同就画成同色。
